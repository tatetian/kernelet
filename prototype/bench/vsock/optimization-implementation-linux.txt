Ordering and demand registration: PASS.

kv_data_ring maps TX to side and RX to side^1 consistently in reserve, commit,
demand registration, and successful-commit notification. A data EAGAIN implies
that the endpoint already has a connection. Connect/accept waits leave demand
NULL and cannot dereference an unconnected endpoint to register ring demand.

kv_request holds kv_lock while snapshotting atomic generation, checking the
operation, and incrementing the appropriate consumer/producer counter. The
counter is nonzero before mutex_unlock, covering the unlock-to-wait interval.
wait_event_interruptible retains its generation/own-death predicate. Every
return from that wait reacquires kv_lock and decrements the saved counter
before retry or exit, including signal and owner-death paths. The defensive
underflow warning reports EIO rather than silently wrapping a counter.

kv_notify_success is called under kv_lock after successful kv_step in both
kv_request and the distinct host kv_io commit path. In mode 2 it checks BOTH
counts on that commit's ring, atomically changes generation, and broadcasts
kv_wait whenever either is nonzero. There is no empty/full heuristic or
waitqueue_active optimization. A committer cannot interleave with registration
under kv_lock, and a commit before wait-queue insertion changes the generation
tested before sleeping. The original lost-wakeup proof therefore applies.

Reservation suppression and zero prefixes: PASS.

Mode 1 and mode 2 suppress only successful RESERVE_TX/RESERVE_RX notification.
These operations establish leases or return without changing availability;
they do not make another request newly ready. Every successful commit clears
its lease before notification. Neither helper nor host commit path tests the
prefix for nonzero, so COMMIT_TX(0) and COMMIT_RX(0) retain their required
lease-release notifications. Rejected commits need not notify unchanged state.
Mode 0 retains broad notification after successful reserves and commits.

Poll and epoll: PASS.

kv_poll chooses kv_poll_wait only in mode 2 and registers with poll_wait before
checking metadata under kv_lock. kv_poll_wait is static module storage. Every
successful data commit in mode 2 unconditionally wakes that queue, regardless
of registered blocking demand. Other modes register poll on kv_wait and keep
their broad commit notifications. The mode is a load-time 0..2 parameter with
0444 permissions, so established subscriptions cannot move between queues at
runtime. The masks and lease-qualified EOF predicate remain unchanged.

Global terminal/control notification: PASS.

klet_vsock_wake always atomically increments generation and wakes kv_wait;
in mode 2 it additionally wakes the separate static poll queue. In modes 0/1
there are no subscribers on that second queue, so skipping it is equivalent to
waking all relevant subscribers. The helper takes no mutex, allocates nothing,
does not inspect endpoint/ring lists or demand counters, and remains usable
from the atomic-context kill path. klet_end publishes dying before calling
klet_kill_carriers, which invokes the broad helper.

Successful shutdown, connect, accept/backlog release and other control steps
fall through kv_notify_success to the broad helper. kv_drop still broadcasts
for ordinary close, pending-listener cancellation, and all-carriers-gone
reaping. Thus host waiters whose own endpoint is not dying still retry after
peer death through changed generation. No new lock acquisition was introduced
into kill and no control notification was narrowed to ring demand.

Half-close and lifetime: PASS.

The existing kv_reserve rule defers empty-ring EOF while a live write-closed
peer retains its TX lease. New producers remain disallowed after SHUT_WR;
already admitted producers may commit normally. Both counter tests on a TX
commit include RX waiters awaiting that lease's resolution, including the
zero-prefix case. Poll retains the corresponding TX-lease EOF guard. Buffered
data still drains before peer-reset error or EOF as previously implemented.

No host file, module, active image carrier, or connection retention contract
was weakened. Payload copying remains outside kv_lock. A retained endpoint
keeps the connection and saved demand pointer alive through wait/relock, even
after its peer is dropped. Safe image ownership still serializes close against
its own operations; image handles are physically reaped only after carriers
are gone. Final connection release now also warns if any demand remains.
The new test-only wait-counter ioctl copies counters under kv_lock, exposes no
pointer, and requires klet_test_hooks; bounded TX/RX delay hooks use the same
gate. Their default values do not introduce production sleeps.

Diagnostic policy: PASS, with interpretation constraint.

Suppressed reserves do not increment per-op wakes. Mode-2 data commits count
blocking broadcasts only when demand exists and separately count unconditional
data poll notifications. Other successful operations retain broad per-op wake
counts. poll_notifies is therefore a count of mode-2 data notifications, not
all terminal/control invocations and not the number of subscribed tasks or
actual scheduler wakeups. Keep that meaning in profiling analysis.

Coverage limitations; no concrete implementation defect established

1. The new wait_demand ioctl observes actual registered same-direction demand,
   a substantial improvement over assuming that a started thread is blocked.
   Lease ownership still uses a 300 ms delay and readiness observations rather
   than an explicit release handshake. Adversarial scheduling can move a later
   action outside that window. Isolated cancellation epoll registration can
   also occur after cancellation under a long scheduling pause. These tests
   exercise the intended overlap in ordinary runs, not deterministically under
   all schedules. Keep the existing delayed-write caveat.

2. registration_stress exercises two connections and 256 checked round trips
   per connection, with time-bounded joins. Its two caller threads inherit the
   main thread's CPU1 affinity and each connection has one caller thread. The
   image peer executes separately, but this is not repeated adversarial
   multi-caller-CPU or multiple-competing-waiter stress on a single ring. The
   separate lease cases cover two same-endpoint operations once per case.
   Stronger stress remains useful follow-up to design-report item G; it is not
   a source-correctness blocker given the checked locking/generation protocol.

3. The interrupted-writer case verifies later communication. The interrupted
   reader case verifies balanced counters and subsequent kill/reclamation,
   rather than a new successful read on that same live connection. The peer
   kill/epoll test does verify owner-wait unregister and final peer reset.
   The backlog case verifies accept releasing a connector; listener kill is
   covered by the earlier full-backlog peer-kill test. A separate listener
   close or blocked-accept interruption case would broaden coverage.

4. Capacity-release epoll tests a full ring; wrapped partial transfers remain
   in the existing functional test, rather than a dedicated wrapped epoll
   capacity test. EOF poll checks and zero-prefix EOF are covered separately
   from epoll lease-restoration. These combinations are not exhaustive.

5. No test here kills an image during its own reserved payload copy. The prior
   all-carriers-gone lifetime argument and admitted host-copy peer-death test
   remain the basis for that unchanged contract. No new proof is claimed.
